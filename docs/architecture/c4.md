# Architecture : modèle C4

Le [modèle C4](https://c4model.com) décrit un logiciel en quatre niveaux de
zoom, du plus large au plus fin :

1. **Contexte** : le système, ses utilisateurs et les systèmes externes.
2. **Conteneurs** : les applications et bases de données qui le composent.
3. **Composants** : l'intérieur d'un conteneur.
4. **Code** : les types et fonctions d'un composant.

Légende commune :

- Rectangle arrondi gris foncé : personne.
- Rectangle bleu : élément du système Arrakis.
- Rectangle gris : système ou élément externe.
- **Bordure en pointillés : prévu, pas encore construit.**

## Niveau 1 : contexte

```mermaid
flowchart TB
  classDef person fill:#08427b,stroke:#052e56,color:#fff
  classDef system fill:#1168bd,stroke:#0b4884,color:#fff
  classDef external fill:#999,stroke:#6b6b6b,color:#fff

  visitor(["<b>Visiteur</b><br/>Personne sans compte"]):::person
  player(["<b>Joueur</b><br/>Membre connecté via Discord,<br/>lié à une carte"]):::person
  admin(["<b>Admin</b><br/>Admin d'une structure esport"]):::person

  arrakis["<b>Arrakis</b><br/>Cartes joueurs, classements,<br/>éditions, inscriptions"]:::system

  discord["<b>Discord</b><br/>Authentification, rôles,<br/>notifications"]:::external
  twitch["<b>Twitch</b><br/>Statut en direct des chaînes"]:::external
  riot["<b>Riot Data Dragon</b><br/>Icônes des champions"]:::external

  visitor -->|"Consulte classements,<br/>cartes, éditions"| arrakis
  player -->|"Personnalise sa carte,<br/>s'inscrit aux éditions"| arrakis
  admin -->|"Importe les résultats,<br/>gère rosters et splits"| arrakis
  arrakis -->|"Connexion OAuth, lecture des rôles ;<br/>publie les résultats (optionnel)"| discord
  arrakis -.->|"Lit le statut live<br/>(optionnel)"| twitch
  arrakis -.->|"Charge les icônes<br/>(optionnel)"| riot
```

Les flèches en pointillés sont des dépendances **optionnelles** : le site
fonctionne sans elles ([ADR 0008](../adr/0008-multi-tenant-et-portabilite.md)).

Le **domaine** (`packages/domain`) n'est pas un conteneur : c'est une
bibliothèque, embarquée à la fois dans l'application web (aperçu d'un import)
et dans les commandes. Il apparaît au niveau 3.

## Niveau 3 : composants

### Le domaine (`packages/domain`)

Les flèches indiquent qui dépend de qui. Aucun module ne dépend de React, de
Supabase ou de Node ([ADR 0001](../adr/0001-monorepo-et-domaine-pur.md)).


## Niveau 4 : code

Zoom sur le cœur du recalcul : les types que `project()` consomme et produit.
C'est le niveau le plus détaillé, et le seul que l'on peut aussi lire
directement dans le code ; il est utile ici pour voir les relations d'un coup
d'œil.

```mermaid
classDiagram
  direction LR

  class Facts {
    splits: SplitFact[]
    editions: EditionFact[]
    matches: MatchFact[]
    performances: PerformanceFact[]
    players: PlayerFact[]
  }
  class EditionFact {
    id, type, date
    splitId: string | null
    prestige
    weightOverride?
    eventMvpPlayerId?
    scoring?: ScoringRules
  }
  class MatchFact {
    id, editionId
    matchNumber
    winnerTeam
    durationSeconds
    mvpPlayerId?
  }
  class PerformanceFact {
    matchId, line, side
    playerId
    role, champion, result
    kills, deaths, assists, gold
  }
  class RatingRules {
    <<interface>>
    weightOf(edition) number
    countsTowardRating(edition) boolean
  }
  class Projections {
    splitRatings: SplitRating[]
    editionHistory: EditionHistoryEntry[]
    editionStandings: EditionStandings[]
  }
  class SplitRating {
    playerId, splitId
    rating: RatingResult
    stats: PlayerStats
    previousRating: number | null
  }
  class RatingResult {
    rating, impact, consistency, clutch
    tier: Tier
  }
  class PlayerStats {
    games, wins, losses, winrate, kda
    kills, deaths, assists
    avgGold, avgGpm, recentForm
  }
  class project {
    <<function>>
    project(facts, rules) Projections
  }
  class computeRating {
    <<function>>
    computeRating(performances) RatingResult
  }
  class computePlayerStats {
    <<function>>
    computePlayerStats(performances) PlayerStats
  }

  Facts *-- EditionFact
  Facts *-- MatchFact
  Facts *-- PerformanceFact
  MatchFact --> EditionFact : editionId
  PerformanceFact --> MatchFact : matchId
  project ..> Facts : lit
  project ..> RatingRules : applique
  project ..> Projections : produit
  project ..> computeRating : utilise
  project ..> computePlayerStats : utilise
  Projections *-- SplitRating
  SplitRating *-- RatingResult
  SplitRating *-- PlayerStats
```
